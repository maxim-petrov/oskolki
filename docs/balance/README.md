# Тесты баланса и механик

Два уровня проверок: быстрые тесты в `npm test` (механика каждой вещи, целостность контента, устойчивость движка) и прогон баланса `npm run balance` (тысячи забегов ботами, отчёт против целей GDD §13).

## Быстрые тесты — `npm test` (~20 с)

| Файл | Что проверяет |
|---|---|
| `tests/items.test.mjs` | каждый предмет, навык, карман и отделка делает то, что написано в подсказке |
| `tests/gear.test.mjs` | правило каждой вещи (каждый цвет поля — вещь в руке), печать, волокита, смена и откладывание вещей |
| `tests/energy.test.mjs` | шкала энергии, «Заряд», «Вне очереди», возврат энергии, бот тратит энергию четырьмя способами |
| `tests/finds.test.mjs` | кошелёк на 99, шкала и сбор находок, перенос в следующий бой, сейф с ключом, две кассы в отделе |
| `tests/enemies.test.mjs` | каждое действие врагов и каждое свойство, меняющее правила боя (турникет, теснота), фазы боссов, распад, затягивание боя, бой с каждым врагом доходит до конца |
| `tests/board.test.mjs` | поле любого размера (5–8 по стороне): раздача без готовых рядов, группы, падение, очередь; обмены, протаскивание, диагонали, замки |
| `tests/content.test.mjs` | у контента есть имя, текст, картинка, цена, пул, открытие; ссылки между врагами, отделами, героями целы; простая вещь в каждом цвете; бот знает цену каждой вещи и умеет применить каждый навык |
| `tests/fuzz.test.mjs` | забеги и бои со случайными сборками: инварианты движка после каждого действия, детерминизм, сохранение и загрузка посреди забега |
| `tests/balance.test.mjs` | дымовой тест баланса: грубые рамки, которые ловят поломку («игру не пройти», «всё зависло») |

Тест, помеченный `todo`, — известная проблема: он виден в выводе, но не валит прогон. Когда проблему чинят, пометку снимают.

## Прогон баланса — `npm run balance`

Полный прогон — 10–20 минут на всех ядрах; `-- --quick` — в 2–3 раза быстрее, те же разделы на меньших выборках. Результат — `docs/balance/REPORT.md` (читать) и `baseline.json` (цифры для сравнения со следующим прогоном: в отчёте появится раздел «Изменения с прошлого прогона»). Код возврата 1, если провалена жёсткая цель.

Что внутри:

- **Забеги** жадного бота и контрольных ботов (случайные вещи, без новых вещей, случайные ходы), каждого героя с открытиями и без, 4 отдела. Победы, прохождение отделов, темп боёв, причины смертей; энергия (ходы вне очереди, «Заряд», навыки), находки и монеты за отдел, сгоревшие на потолке кошелька монеты.
- **Встречи**: каждая группа врагов каждого отдела против реальных сборок из того же места отдела.
- **Лаборатория**: реальные сборки перед боями (из забегов) переигрываются с изменением — плюс предмет, другой навык, карман, вещь в руке вместо простой того же цвета, улучшенная вещь. Сколько здоровья это сберегает, по отделам.
- **Предмет или вещь со старта**: целый забег на тех же сидах — разница побед и этажей; простые вещи, улучшенные со старта; Волокита в мешке.
- **Урон за ход**: сборки отделов против неподвижного босса; какие пары предметов разгоняют урон сильнее суммы.
- **События**: итог каждого выбора, доигранный до конца.
- **Хаос**: случайные вещи (в руке и запасные, улучшенные), волокита и предметы против любых врагов — движок не должен ломаться.

Цели и их пороги — `game/balance/targets.ts` (жёсткие взяты из GDD §13).

### Проверить правку до того, как менять игру

```
npm run balance -- --quick --patch=docs/balance/patches/example.mjs
```

Модуль-правка меняет цифры контента (отделы, враги, предметы, вещи) только на время прогона. Отчёт ляжет в `docs/balance/whatif/<имя правки>/` с разделом «Изменения относительно основного прогона».

## Добавили предмет, вещь, врага или событие

1. `npm test` — упадёт тест-реестр: «нет проверки для …». Дописать проверку в `tests/items.test.mjs`, `tests/gear.test.mjs` или `tests/enemies.test.mjs` — что именно делает новая вещь (по тексту подсказки).
2. Новая вещь — дать ей цену для бота в `GEAR_SCORE` (`game/bot.ts`; простая вещь цвета — 0), сначала на глаз. Новый навык с целью (клетка, столбец, враг) — научить бота его применять (`combatAction`).
3. `npm run balance -- --quick` — новая вещь сама попадёт во все таблицы. Смотреть флаги: 🔥 имба, 💤 слабый, ⛔ мешает, ⬇️ хуже простой вещи, 🔺 опасная встреча.
4. Цены вещей для бота: в таблице «Вещи» колонка «По замеру» — подсказка из лаборатории (сколько вещь в руке сберегает в бою против простой того же цвета и что даёт целому забегу), `--only=lab,runab` считает её за ~10 минут. Новые цены проверять целыми забегами: правка с ценами (`--patch`, `Object.assign(GEAR_SCORE, {...})`) против текущих — оставить, только если жадный бот не стал слабее.
5. Перед слиянием — полный `npm run balance`, закоммитить обновлённые `REPORT.md` и `baseline.json`.

## Устройство

- `game/balance/lab.ts` — бой и забег ботом по спецификации (сборка, отдел, враги, читы для замеров), журнал боёв, снимки сборок.
- `game/balance/invariants.ts` — правила, которые движок держит после любого действия.
- `game/balance/trials.ts` — выбор в событии, доигранный до конца.
- `game/balance/targets.ts` — контракт баланса.
- `scripts/balance.mjs` + `scripts/balance-worker.mjs` — прогон на всех ядрах и отчёт.
- `tests/scene.mjs` — сцены для проверок механик: поле из клякс, на которое тест кладёт фишки нужного цвета (`put`, `line`, `queue`; `RED3`/`BLUE3`/`VIOLET3`/`GOLD3`; вещь по id кладёт фишку её цвета и берёт вещь в руку; `scene({ gear, ups, tape })`).

Боты (`game/bot.ts`) — нижняя граница умения: жадный выбирает ход по первой волне, вещи — по таблице ценности (`GEAR_SCORE`), меняет вещи в бою, если так заметно лучше; тратит энергию на навык, «Заряд» (когда заряженный ход заметно сильнее) и «Вне очереди» (перед тяжёлым ударом). Ластик из кармана по умолчанию тратит только на кляксы; `erase: 'match'` — ловит им совпадения (так играет опытный игрок).
