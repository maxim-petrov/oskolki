# Тесты баланса и механик

Два уровня проверок: быстрые тесты в `npm test` (механика каждой вещи, целостность контента, устойчивость движка) и прогон баланса `npm run balance` (тысячи забегов ботами, отчёт против целей GDD §13).

## Быстрые тесты — `npm test` (~20 с)

| Файл | Что проверяет |
|---|---|
| `tests/items.test.mjs` | каждый предмет, навык, карман и отделка делает то, что написано в подсказке |
| `tests/cards.test.mjs` | правило каждой фишки |
| `tests/enemies.test.mjs` | каждое действие врагов, фазы боссов, распад, затягивание боя, бой с каждым врагом доходит до конца |
| `tests/content.test.mjs` | у контента есть имя, текст, картинка, цена, пул, открытие; ссылки между врагами, отделами, героями целы; бот знает каждую фишку и умеет применить каждый навык |
| `tests/fuzz.test.mjs` | забеги и бои со случайными сборками: инварианты движка после каждого действия, детерминизм, сохранение и загрузка посреди забега |
| `tests/balance.test.mjs` | дымовой тест баланса: грубые рамки, которые ловят поломку («игру не пройти», «всё зависло») |

Тест, помеченный `todo`, — известная проблема: он виден в выводе, но не валит прогон. Когда проблему чинят, пометку снимают.

## Прогон баланса — `npm run balance`

Полный прогон — 10–20 минут на всех ядрах; `-- --quick` — в 2–3 раза быстрее, те же разделы на меньших выборках. Результат — `docs/balance/REPORT.md` (читать) и `baseline.json` (цифры для сравнения со следующим прогоном: в отчёте появится раздел «Изменения с прошлого прогона»). Код возврата 1, если провалена жёсткая цель.

Что внутри:

- **Забеги** жадного бота и контрольных ботов (случайные фишки, без фишек, случайные ходы), каждого героя с открытиями и без, 4 отдела. Победы, прохождение отделов, темп боёв, причины смертей.
- **Встречи**: каждая группа врагов каждого отдела против реальных сборок из того же места отдела.
- **Лаборатория**: реальные сборки перед боями (из забегов) переигрываются с изменением — плюс предмет, другой навык, карман, отделка, две копии фишки. Сколько здоровья это сберегает, по отделам.
- **Предмет или фишка со старта**: целый забег на тех же сидах — разница побед и этажей.
- **Урон за ход**: сборки отделов против неподвижного босса; какие пары предметов разгоняют урон сильнее суммы.
- **События**: итог каждого выбора, доигранный до конца.
- **Хаос**: случайные колоды и предметы против любых врагов — движок не должен ломаться.

Цели и их пороги — `game/balance/targets.ts` (жёсткие взяты из GDD §13).

### Проверить правку до того, как менять игру

```
npm run balance -- --quick --patch=docs/balance/patches/example.mjs
```

Модуль-правка меняет цифры контента (отделы, враги, предметы, фишки) только на время прогона. Отчёт ляжет в `docs/balance/whatif/<имя правки>/` с разделом «Изменения относительно основного прогона».

## Добавили предмет, фишку, врага или событие

1. `npm test` — упадёт тест-реестр: «нет проверки для …». Дописать проверку в `tests/items.test.mjs`, `tests/cards.test.mjs` или `tests/enemies.test.mjs` — что именно делает новая вещь (по тексту подсказки).
2. Новая фишка — дать ей цену для бота в `CARD_SCORE` (`game/bot.ts`). Новый навык с целью (клетка, столбец, враг) — научить бота его применять (`combatAction`).
3. `npm run balance -- --quick` — новая вещь сама попадёт во все таблицы. Смотреть флаги: 🔥 имба, 💤 слабый, ⛔ мешает, ⬇️ хуже простой фишки, 🔺 опасная встреча.
4. Перед слиянием — полный `npm run balance`, закоммитить обновлённые `REPORT.md` и `baseline.json`.

## Устройство

- `game/balance/lab.ts` — бой и забег ботом по спецификации (сборка, отдел, враги, читы для замеров), журнал боёв, снимки сборок.
- `game/balance/invariants.ts` — правила, которые движок держит после любого действия.
- `game/balance/trials.ts` — выбор в событии, доигранный до конца.
- `game/balance/targets.ts` — контракт баланса.
- `scripts/balance.mjs` + `scripts/balance-worker.mjs` — прогон на всех ядрах и отчёт.
- `tests/scene.mjs` — сцены для проверок механик: поле из клякс, на которое тест кладёт нужные фишки.

Боты (`game/bot.ts`) — нижняя граница умения: жадный выбирает ход по первой волне, фишки — по таблице ценности. Ластик по умолчанию тратит только на кляксы; `erase: 'match'` — ловит им совпадения (так играет опытный игрок).
